# Accounts, Characters & Classes

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

## Accounts & Characters

One Supabase account (`auth.users`/`players`) can have up to **5 characters** (`characters` table, `slot_index` 1-5).

- **Account-level** (`players` table): `last_seen_version`, `bank_gold`/`bank_comets`/`bank_fallen_stars` (account-wide currency bank), `unlocked_classes` (text array, default `['hunter']`), `ascension_points` (account-wide, see Marketplace section), `warehouse_points`→renamed `bank_points`, `gear_composition_points` (jsonb per slot_type), `composition_stones_banked` (jsonb), `comet_bank_count`/`fallen_star_bank_count`, `account_attack_bonus_pct`/`account_drop_bonus_pct` (see Achievements).
- **Character-level** (`characters` table): `class`, `level`, `exp`, `name`, `gold` (personal wallet, default 5,000 for new characters — placeholder, unresolved), `comet_count`/`fallen_star_count`/`comet_scroll_count`/`fallen_star_scroll_count`, one `equipped_*_id` column per equip slot (`equipped_weapon_id`/`equipped_ring_id`/`equipped_necklace_id`/`equipped_boots_id`/`equipped_hat_id`/`equipped_coat_id`/`equipped_quiver_id`), `current_zone`, `selected_monster_id`, `last_active_at`, `composition_stones` (jsonb, tiers "1"-"4"), `lottery_ticket_count`, `lucky_free_ticket_claimed_at`. Items (`item_instances.owner_id`) belong to a specific character, not the account.
- **Character creation**: only Hunter is selectable today. Twin-soul/Wuxia/Juggernaut show locked with a placeholder condition ("Unlocks after a Hunter reaches level 100" — unresolved). No mechanism yet adds to `unlocked_classes` automatically. Class is fixed at creation.
  - **Starter weapon**: Hunter auto-granted + auto-equipped a Lucky Bow at creation (`grantStarterBow` in `useCharacterRosterStore.ts`), matching Wooden Sword's stats (`physical_attack: 5`, 25g) but Hunter-only, standalone `item_family: 'lucky-bow'` — kept out of the Bow chain's Level Upgrade progression and out of random kill-drops (`NON_DROPPABLE_FAMILIES`). Not retroactive.
- **Character select layout**: single-column list (one card per row: name/class/level, Play/Delete).
- **Character naming**: format `^[A-Z][a-z]*$`, enforced client-side (`CHARACTER_NAME_PATTERN`) and via DB CHECK constraint `characters_name_format_check`. Unique across every account (DB UNIQUE `characters_name_unique`). Postgres error 23505→"already taken", 23514→bad format.
- **Character deletion**: requires typing exact name to confirm; cascades to `item_instances`/`potion_stacks` via `on delete cascade`. Needs DELETE RLS policy + `grant delete` on `characters` (`account_id = auth.uid()`).
- **Login flow**: `CharacterSelectScreen` shows all 5 slots before gameplay; `GameShell` only renders once a character is chosen. "Switch Character" clears active character without signing out. Active-character selection persists across refresh via `localStorage` (`ascension-last-character:<accountId>`, `useActiveCharacterStore.ts`), resumed once per fresh page load only. A stale/invalid stored id self-heals back to character select.

## Classes

4 classes, confirmed mapping: Hunter = Archer (ranged), Twin-soul = Trojan (dual-wield melee), Wuxia = Taoist (mystic backsword), Juggernaut = Warrior (heavy tank).

- **Active skill system (2026-10, first entry, Wuxia's Thunder)** — see `CLAUDE.combat-and-loot.md`'s Combat section. An equipped skill replaces the class's regular auto-attack (own attack interval + magic-only damage) rather than being a stackable ability. UI lives on the Equipment tab's new Skills/Passives card. Per-skill leveling and every other class's own skill(s) are still deferred.
- **Twin-soul/Wuxia/Juggernaut real gear catalogs (2026-08-18, prep-only — not yet playable)**: same original-names/paced-off-Conquer-reference approach as Hunter's own catalog (see `CLAUDE.gear-and-forge.md`'s Gear system section), seeded in `20260909000000_wuxia_gear_catalog.sql`/`20260911000000_twin_soul_gear_catalog.sql`/`20260912000000_juggernaut_gear_catalog.sql`. Every row's `required_class` is one of `'wuxia'`/`'twin-soul'`/`'juggernaut'` (never `null`, since `null` means visible to the live Hunter class too). Mapping: Wuxia = Backsword (weapon, exclusive) + Cap (hat) + Robe (coat) + Bracelet (**ring** slot) + Bag (**necklace** slot). Twin-soul = Club/Sword/Blade (all 3 one-handed weapon families) + Coronet (hat) + Mail (coat). Juggernaut = the same Club/Sword/Blade pool as Twin-soul (own `item_family` keys per class, e.g. `club-twinsoul` vs `club-juggernaut`, so chain-upgrade never crosses classes) + Maul (exclusive two-hander, reflavored from the source data's caster "Wand" into a physical-attack weapon to fit Juggernaut's 0-Spirit design) + Helmet (hat) + Armor (coat) + Shield. Only the weapon chains use the fine per-level 120-130 breakdown (mirroring Bow's own precedent); headgear/chest/ring/necklace use coarser breakpoints instead.
  - **Weapon curves are ratio-scaled per family, not flat Bow parity (rescaled 2026-08-18, `20260913000000_rescale_weapon_curves.sql`)**: the first pass reused Bow's exact attack/dexterity numbers verbatim for every new weapon, which erased the real relative power differences between weapon types. Fixed by scaling each family's curve by its own real level-130 Max Atk ratio against Bow's own real level-130 Max Atk (Shadow Bow, 2558 — `reference/conquer-items/bows.md`), applied across all 33 of Bow's level breakpoints: Longsword ×0.87 (2220/2558), Blade ×1.01 (2575/2558), Maul ×1.16 (2970/2558), Club ×1.22 (3127/2558). Dexterity is re-derived from each family's own new attack value via the existing `round(atk * 0.15)`, floored-at-1 rule — not a second scaling of Bow's own dexterity numbers. Twin-soul's off-hand slot is 3 real per-weapon-type chains (`club-offhand-twinsoul`/`longsword-offhand-twinsoul`/`blade-offhand-twinsoul`), each an exact stat mirror of its main-hand counterpart — not one generic invented family, since the off-hand item is meant to be whichever one-hander the player is dual-wielding.
  - **Backsword's multiplier corrected again the same day (`20260914000000_fix_backsword_magic_atk_column.sql`)**: `reference/conquer-items/backswords.md` has three numeric weapon columns (Max Atk / Min Atk / Magic Atk) — the rescale above mistakenly used Max Atk (822 at level 130, the physical/Strength-scaled column, meaningless for a 0-Str Wuxia) instead of the actual Magic Atk column (1167 at level 130 Normal tier). Corrected multiplier ×0.4562 (1167/2558), was ×0.3213. Same methodology otherwise (applied across Bow's 33 breakpoints, dexterity re-derived per-level from the corrected attack value). Worth double-checking any future source-data extraction for items with more than 2 numeric weapon columns — easy to grab the wrong one.
  - **All 482 items renamed for zero cross-family collisions (`20260915000000_rename_new_class_items.sql`)**: the original naming reused the same top-tier band words (Astral/Celestial/Eternity) identically across every single family, and Club/Sword/Blade additionally shared one prefix-word list between them. Fixed by giving each weapon type, armor slot, and accessory line its own fully distinct vocabulary (194 unique words) — the only intentional exception is Twin-soul's and Juggernaut's duplicate copies of the same weapon type (e.g. `club-twinsoul`/`club-juggernaut`/`club-offhand-twinsoul`), which still share names since they're the same conceptual item. Backsword alone keeps Astral/Celestial/Eternity as its own exclusive top-tier band (fits its mystic theme). Twin-soul's chest slot displays as "X Armor" now instead of "X Mail" (the `item_family` DB key is still `mail`, only the shown name changed) — its own word list is distinct from Juggernaut's separate "X Armor" chest line, so the two classes' Armor items never collide despite sharing the same suffix word. Also applied a general shortening pass: two-word compound names keep whichever half reads as the nicer mage/fantasy word and drop the other (e.g. Willowfang → Willow, Duskleaf → Dusk).
  - **Weapon chains gained level 5 and level 10 entries (`20260916000000_add_weapon_level_5_10.sql`)**: Club/Sword/Blade/Maul/Backsword all now start at level 5 (previously 8), matching how Sword/Blade/Backsword's own source data starts (`reference/conquer-items/{swords,blades,backswords}.md`), applied consistently to Club/Maul too even though their real source starts at 15. The old level-8 row just moves to level 10 unchanged (name and stats already sat correctly below the level-15 value); a new level-5 row was added per weapon type with a fresh name (Sprout/Knot/Page/Nick/Pebble) and a fresh stat value, same `round(bowBaseline * multiplier)` methodology as the rescale. 493 total items now (was 482).
- **Second-hand slot (2026-08-18)**: `characters.equipped_quiver_id`/`item_templates.slot_type: 'quiver'` is the paper doll's Off-hand/Shield tile, repurposed per class rather than getting a new column/slot_type — Hunter keeps its stat-less ammo Quiver, Twin-soul gets a real off-hand weapon (item_family `offhand-twinsoul`), Juggernaut gets a real Shield (item_family `shield`, carries a new `max_hp` base_stats key folded into `EquipmentBonus.gearHpBonus` → `derivedStats.ts`'s `hp`), and Wuxia gets a non-interactive dimmed echo of Main Hand (`EquipmentPanel.tsx`/`CharacterLoadoutModal.tsx`'s `SECOND_HAND_BY_CLASS` map) — no item is ever placed in Wuxia's slot. `resolve_combat_gather_state`/`world_boss_gather_attack_state` (migration `20260910000000_second_hand_slot_stats_in_combat.sql`) were fixed to include the quiver-slot item in their server-side stat gathering, which they'd previously skipped entirely since Hunter's Quiver never had real stats. Shield's Defense/HP are client-only (never server-simulated, same as every other HP source) and have no durability yet (`DURABILITY_RANGE_BY_CATEGORY` has no `'quiver'` entry, deliberately — adding one would also start decaying Hunter's Quiver).
- **Hunter ammo — no economy, just an equip gate**: a Hunter can attack freely as long as Quiver is equipped (`characters.equipped_quiver_id` non-null) — no stack, no count, no consumption, no purchasing needed beyond owning one. `useCombatStore.runTick` checks `useEquipmentStore.getState().equippedIds.quiver` (client); `resolve-combat` checks `character.equipped_quiver_id` (server). A blocked attack logs `'no-quiver'` and triggers `useNoQuiverWarningStore`, shown by `QuiverWarningHud.tsx` (shows nothing while equipped). Quiver still auto-granted/auto-equipped at creation, buyable in Shop if lost.
- **Tab navigation**: `TabNav`'s buttons each select a full page via `useTabStore` (`activeTab: TabId`). `GameShell` renders the active tab at full width plus a persistent top HUD strip (`ExpBar`/`QuiverWarningHud`/`InventoryFullWarningHud`). Combat = `CombatPage.tsx` (zone picker, roster/fight panel, and Inventory). Equipment = `EquipmentTabPage.tsx` (paper-doll + Stats + Inventory grid below). Forge/Market/Shop/Bank/Achievements/Lucky are their own panels.
  - **Shop** (`ShopPanel.tsx`): sub-tabs Weapons/Armor/Jeweller/Potions/Repair (Arrows tab removed — no ammo economy; Jeweller split out of Armor 2026-08-07 for rings/necklaces). Real PNG art per sub-tab (`public/shop-tab-icons/`, 320x320, same sharp resize-cover pipeline as `public/nav-icons/`), replacing the old emoji placeholders. Weapons/Armor/Jeweller filter `item_templates` by `slot_type` and class (`required_class` null or matching), sorted by `required_level`. Buying spends gold client-side then calls `grantItemDrop(template, true)` (full-inventory triggers `InventoryFullModal` same as a kill drop). Two-column layout (`grid lg:grid-cols-2`): buy controls left, reused `InventoryPanel` (`columns={5}`) right, via `enableSelling` prop → "Sell (N gold)" button. `sell_item(item_id)` is a `SECURITY DEFINER` RPC (migration `20260730060000_add_sell_item.sql`) — **PLACEHOLDER sell-price formula**: half of buy price scaled by `QUALITY_STAT_MULTIPLIERS` (`equipmentBonus.ts`'s `previewSellPrice`, kept in sync with SQL); composition level ignored. Bulk sell: per-tile checkbox (only when `enableSelling`), "Sell Selected (N gold)" bar, "Select All Normal" shortcut; loops `sell_item` sequentially. Buy-preview rows show `InventorySlot` + hover tooltip via `buildGearTooltip` fed a synthetic preview `ItemInstance` (Normal quality, level = `required_level`, no composition) matching what `grantItemDrop` actually creates.
- Gear unlock levels are still placeholders.

**Stats — attribute-point system**: Strength, Agility, Vitality, Spirit.
- Vitality → +24 HP/point. Strength/Agility/Spirit → +3 HP/point each. Spirit → +5 MP/point.
- Physical attack scales off Strength. Magic attack scales off Spirit. Attack speed is fixed by weapon type, not stat-driven. Agility governs accuracy/dodge.
- Class starting (level 1) attributes: Warrior/Trojan = Str 5, Agi 2, Vit 3, Spi 0. Taoist = Str 0, Agi 2, Vit 3, Spi 5. Archer = Str 3, Agi 5, Vit 2, Spi 0.
- **Auto-allotment by level (implemented)**: attributes grow automatically as a character levels (no manual point-spending), anchored at promotion tiers 1/15/40/70/100/110/120(/130). `ATTRIBUTE_ANCHORS`/`getAttributesForLevel` in `src/game/stats/classes.ts` (mirrored in `resolve-combat/index.ts` — must stay in sync) **linearly** (not geometrically) interpolates between nearest anchors — linear because several attributes are pinned at exactly 0 for a class. `useCharacterStore.attributes` is recomputed on every `level` change via a `useProgressionStore.subscribe(...)` cross-store hook. **120 and 130 are NOT sourced** — extrapolated in a straight line from the 100→110 rate; revisit if better data surfaces. Cross-validated against real screenshots (Trojan/Archer): matched exactly except Archer's level-15 Agility anchor, corrected to 30 (both in `classes.ts` and the `resolve-combat` mirror). Only applies for levels 1-130 — see "Ascend" in `CLAUDE.progression.md` for post-cap.
- **`StatsPanel` collapsed by default** behind "Show ▼"/"Hide ▲". Attack shown as a range (`damageRangeFromMidpoint`), not a flat number.

**Gear slots**: Headgear, Body armor, Shield (Warrior/Juggernaut only), Boots, Earrings, Necklace, Ring, Heavy Ring, Bracelet, Bag, Riding Crop, plus class-specific one-handed weapons (Sword, Backsword, Blade, Hook, Whip, Axe, Hammer, Club, Scepter, Dagger, Arrows) and two-handed (Bow, Glaive, Poleaxe, Spear, Wand, Halberd), plus special slots: Talisman, Garment, Dragon Soul, Martial Soul. Exact per-class slot assignment is **unresolved — needs a follow-up finalization pass**.

**Class Promotion (v1.97.0, cosmetic only — no stat/combat effect)**: `characters.promotion_level` (default 0) tracks a character's highest reached tier — a distinct concept from the unrelated, unstored `PROMOTION_TIER_ANCHORS` EXP-pacing curve in `expCurve.ts`/`resolve-combat`. Every character starts as **"Novice \<ClassName\>"** (e.g. "Novice Hunter") before its first promotion — a fixed convention derived from `CLASS_DEFINITIONS`' `displayName` (`promotionHelpers.ts`'s `startingTitle`), not a `promotion_tiers` row. Data-driven via `promotion_tiers` (class/level/title/`items_required`/`award_items` jsonb, `skills_unlocked` text[]), so new classes are a pure seed-row addition, no code changes. `promote_character(character_id)` RPC (guaranteed success, no RNG, once level + cost are met) consumes cost and grants awards in one transaction, updating `promotion_level`; client wiring is `usePromotionStore.ts` (loads tiers once, wraps the RPC) + `promotionHelpers.ts` (`getCurrentPromotionTitle`/`getNextEligiblePromotionTier`, pure functions like `getAttributesForLevel`) + a Promote button/title line in `EquipmentPanel.tsx` opening `PromotionModal.tsx`. `skills_unlocked` is inert flavor text only — no ability/skill system exists yet (deferred), may later gate skill unlocks.

Seeded so far for Hunter only — 5 tiers, no level-120 tier (matches the real game's actual promotion cap and the already-unsourced level-120 attribute anchor). Titles/items/skills went through two renames before settling (screenshot placeholders → an invented-naming pass `20260901010000_promotion_rename_pass.sql` → item/title adjustments `20260901020000_promotion_item_adjustments.sql`, after the user pointed out several items already belonged to other systems).
