# Visual Design System

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

**Gold/steel "Ascension" theme (2026-08-14, confirmed app-wide)** — supersedes the earlier plain-typography/no-gradients look entirely. Cinzel serif headings, gradient gold (`#fff3a1→#d4af37→#997a15`) and steel (`#ffffff→#c0d1e3→#7a8b9e`) text, thin gradient-bordered cards, gold-gradient CTA buttons with a hover glow.

**"Prism Obsidian & Light Sweep" chrome pass (2026-08-28)** — reskinned the above, gold/steel palette unchanged. Cards/chips/selects moved from rounded corners to chamfered (clip-path-cut) corners; `.btn-gold`/`.btn-gold-active`/`.btn-steel`/`.btn-glow` all gained a glassy top highlight plus a diagonal shine that sweeps across on `:hover` (`::before`/`::after`, needs `overflow: hidden` on the host — see the ember-safe gotcha below for the one exception). `.btn-glow`'s idle background is now `color-mix(in srgb, var(--glow-base) …%, <dark>)` instead of a flat neutral dark, so it reads as "a dark version of its own color" per button. `AscensionCard`'s title also moved from a floating pill-shaped ribbon (overlapping the card's top border, pulsing gold stars either side) to an in-flow header row inside the card's own padding — a plain gold rule line (`.ascension-card-header-line`, transparent→gold→transparent) on either side of the Cinzel heading, no stars, no absolute positioning. `GameShell.tsx`'s `mt-2 lg:mt-4` on its outer `AscensionCard` (previously compensating for the old ribbon poking up above the frame) was removed along with it — don't re-add spacing compensation for a ribbon that no longer exists.
- **Ember-hosting elements can't be clipped.** `EventEmberBorder` (`src/game/hud/eventEmberBorder.tsx`) renders particles that anchor up to ~56% out from their parent's center — genuinely outside the parent's own box, by the component's own documented contract ("Parent must be `position: relative` and not clip overflow"). Its hosts are `.btn-gold`/`.btn-gold-active` on exactly three call sites (`TabNav.tsx`'s Idling/LuckyLad tabs, `MobileBottomNav.tsx`'s FAB — the inner `<span>`, not the outer borderless `<button>` — and `CombatPage.tsx`'s Events sub-tab) plus `AscensionCard` via its `activeEventColor` prop (`WorldBossCard.tsx`/`GoldDonationCard.tsx` only). Two different fixes, because the two cases have different shapes:
  - **Buttons**: everywhere else `.btn-gold`/`.btn-gold-active` is used (every plain CTA via `Button.tsx`'s `primary` variant, LuckyLad's bulk-draw button, `SkillsPanel`'s Skills/Passives toggle, `CombatPage`'s Hunting/Mining toggle) never hosts embers, so the sweep/`overflow:hidden` is the class's own default. The three ember-hosting call sites opt OUT by adding `.btn-ember-safe` to `className` whenever their own event-color prop is truthy (index.css compound selectors `.btn-gold.btn-ember-safe`/`.btn-gold-active.btn-ember-safe` revert to `overflow: visible` and unset the pseudo-elements' `content`).
  - **`AscensionCard`** (2026-08-28, revised same day after the user reported World Boss/Gold Donation looking visually out of step with the rest of the redesign — an earlier pass used the same opt-out-modifier-class approach as buttons, but since these two cards host live embers almost the entire time they're rendered, that meant they almost never actually got the chamfer, unlike the button case where the exception is genuinely rare): `.ascension-card-frame` chamfers **unconditionally** now, no opt-out class. Instead, whenever `activeEventColor` is set, `AscensionCard.tsx` renders `<EventEmberBorder>` as a **sibling** of the frame (inside an unclipped `position: relative` wrapper sized to match it) rather than a child of it — the frame gets to keep its own clip-path because the thing that can't tolerate clipping is no longer inside it. The wrapper only exists in the `activeEventColor` branch; the plain (no-event) branch is untouched, still just the bare frame div, so this costs nothing for the vast majority of `AscensionCard` usages that never pass this prop.
  If a future element needs both the ember effect and a clip-path/overflow treatment, prefer the sibling-wrapper approach over an opt-out modifier class unless the element's own ember-active state is genuinely rare — an opt-out only reads as "the default" if the exception is actually uncommon.

- **Shared primitives, `src/components/ui/`** — use these for any new UI, don't hand-roll card/button/select markup:
  - `AscensionCard` — the gradient-frame card. `title` prop renders an in-flow header row (gold rule line either side of a steel-gradient Cinzel heading, see the Prism Obsidian bullet above); omit it for a plain frame with no title. `titleSize="large"` (2026-08-14, revised same day after the user flagged the first pass — see the Page-level framing bullet below) is `'default'`-sized below `lg` and roughly doubles at `lg`+; used exactly once, by `GameShell.tsx`'s own outer frame, never by an individual tab's own component. Everything else (Zone & Monster, Storage, Achievements, the Equipment gear box's character-name heading, ...) stays `'default'` at every width.
  - `Button` — `variant: 'primary' | 'secondary' | 'danger'`. `primary` = gold CTA (the one positive action of a panel — Buy/Confirm/Claim/Fight-style), `.btn-gold`. `secondary` = steel gradient (Cancel/Back/neutral), `.btn-steel` (2026-08-28 — was a flat `border-slate-700` outline with no theme chrome at all, which read as "unstyled" next to any gold button beside it; now mirrors `.btn-gold`'s idle-dark/hover-bright-gradient-plus-glow structure on the steel token ramp). `danger` = red outline (Delete/destructive), still a plain `border-rose-700` outline — deliberately outside the gold/steel chrome. No width is set — pass `className="w-full"` etc. yourself.
  - `Select` — wraps a native `<select>` in the same chrome with a custom arrow overlay; preserves per-`<option>` inline `style` colors (e.g. level-diff coloring) unchanged.
- **`TooltipActionPopover`'s button bar is fixed at `w-64`, matching `ItemTooltip`'s own width** (2026-08-28) — without a width of its own it just grew to fit its buttons instead of wrapping, so a long label (Bundle/Open) sharing a row with Bank/Bank All pushed the whole bar wider than the tooltip above it. A 3-action list (Bundle/Open/Claim + two shorter actions) puts the first action on its own full-width row and splits the remaining two across the row below — plain `flex-wrap` won't do this split on its own (each button's text wraps internally before the whole button drops to a new row), so it's explicit: `actions.length > 2` peels off `actions[0]` into its own `w-full` `Button`, the rest render in a `flex-wrap` row beneath. A 1- or 2-action list is unaffected (single row, unchanged).
- **CSS tokens/classes, `src/index.css`** — `.ascension-card-frame`/`.ascension-card-inner`/`.ascension-card-header`/`.ascension-card-header-line` (the card chrome the component wraps), `.ascension-chip-frame`/`.ascension-chip-inner` (compact variant — also what `ItemTooltip`/`TooltipActionPopover`'s button bar use now, 2026-08-28, replacing a plain `border-slate-700` panel), `.text-gradient-gold`/`.text-gradient-steel`, `.btn-gold`/`.btn-steel`, `.text-heading-label` (small-caps Cinzel field label), `.ascension-glow-pulse` (breathing gold glow, `currentColor`-based like the pre-existing `.accent-glow`).
- **Any modal dialog** (`WhatsNewModal`, `OfflineProgressModal`, `SettingsModal`, ...) should use the `ascension-card-frame`/`ascension-card-inner` shell + `Button`, not a hand-rolled `rounded-2xl border border-slate-800 bg-slate-900` panel — several modals were still on the old pattern until an audit pass (2026-08-28) caught them; check any new one against this before assuming it's themed.
- **`-webkit-tap-highlight-color: transparent` is set globally on `button`/`a`/`[role="button"]`** (2026-08-28) — a plain `<button>` wrapping a rounded child (e.g. `ForgeHub`'s tile buttons around `AscensionCard`) has no border-radius of its own, so mobile WebKit/Chrome's default tap-highlight rectangle can poke past the child's rounded corners. Real precaution, but this was NOT the cause of the ForgeHub gold-gap bug below — don't reach for this fix again for a similar-looking artifact without checking box-model first.
- **`.ascension-card-inner` has explicit `height: 100%`** (2026-08-28, the actual fix for "gold sliver at the bottom of a Forge tile") — `.ascension-card-frame` stretches to match its CSS Grid row's tallest sibling (via `h-full`, e.g. ForgeHub's tiles), but without this rule `.ascension-card-inner` only sizes to its own content. Any row where one tile's description wraps to fewer lines than its row-mate's (Salvage next to Composition, at some viewport widths) left a gap between the shorter inner panel and the taller stretched frame, exposing the frame's own raw gold/steel gradient background as a visible sliver — worse on narrow/mobile widths where text-wrap mismatches between row-mates are more common. `height: 100%` is a no-op wherever the frame's height is auto (nearly every other `AscensionCard` usage), so this is safe globally. Diagnosed by rendering `ForgeHub`'s actual compiled markup+CSS in a headless browser and comparing each tile's frame vs. inner `getBoundingClientRect()` — not visible from reading the JSX/CSS alone.
- **App shell chrome (2026-08-14)** — the page background (`GameShell.tsx`'s root div), header, and mobile bottom nav all use `bg-[...]` with the `--ascension-ink`/`--ascension-ink-soft` tokens (matching `.ascension-card-inner`'s interior) instead of the old plain slate colors. `.ascension-edge-b`/`.ascension-edge-t` — a horizontal gold/steel/gold `border-image` rule (same 3-stop palette as the card frame, rotated 90°) for a straight top/bottom edge on non-boxed elements (header's bottom edge, bottom nav's top edge). `.ascension-chip-frame`/`.ascension-chip-inner` — compact gradient-border-via-padding pill, same technique as the card frame but smaller radius and no drop shadow, for small HUD elements (ExpBar, PlayersOnlineHud, ChatButton, header's Switch Character/Settings/Sign out buttons); add `.is-interactive` alongside `.ascension-chip-frame` on actual buttons for a brighter hover gradient — omit it on plain info pills so they don't read as clickable.
- **Top-level nav buttons** — `TabNav.tsx`'s 8-tab desktop grid and `MobileBottomNav.tsx`'s circular Idling FAB use `.btn-gold`/`.btn-gold-active` (2026-08-16, supersedes the plain amber-border toggle these used to have) — `.btn-gold` for the idle state, `.btn-gold-active` (index.css — the permanently-lit variant of `.btn-gold`'s own `:hover` gradient, applied instead of `.btn-gold`, never alongside it) for whichever tab is currently open. `MobileBottomNav.tsx`'s four side tabs (Equip/LuckyLad/Tavern/Achiev.) and the Tavern rollup's own collapsed button do NOT use this — see the borderless-pill entry below.
- **`MobileBottomNav.tsx`'s four side tabs are borderless, not boxed** (2026-08-28 redesign, requested by the user — the old per-button `.btn-gold`/`.btn-gold-active` box made all five bar items read as equally-weighted boxed buttons, competing with the Idling FAB instead of deferring to it). The outer `<button>` is a plain unstyled tap target; only the active tab's icon+label sits inside a small `.nav-pill-active` pill (index.css — same gradient/glow as `.btn-gold-active` but no border, sized to hug its own content via an inner `<span>` rather than stretching edge-to-edge). Idle tabs get no background at all, just `text-slate-400`. This also retired the old `outerCorner` prop on `NavButton` (previously matched a boxed button's corner to the bar's own `rounded-b-[3rem]` mask) — moot now that idle buttons have no box, and the active pill sits well clear of the bar's physical edge. The row's `px-2` inset (keeps tap targets off the phone's physical screen edge) is unrelated and unchanged — don't reintroduce edge-flush buttons when touching this again.
- **CombatPage's Hunting/Mining/Events switcher also uses `.btn-gold`/`.btn-gold-active`** (2026-08-16, same pass as the top-level nav restyle, applied here on a follow-up request) — Mining stays `disabled` rather than getting its own dimmed-opacity wrapper, relying on `.btn-gold:disabled`'s built-in dimming like every other disabled button in the app.
- **Active/selected toggle state elsewhere** (other in-page sub-tab pickers — not a `Button`, since `Button` has no notion of a selected state): still the older gold accent (`border-amber-400 bg-amber-500/10 text-amber-300`), not the app's old sky-500 accent. Achievements' Character/Account/Pets, Marketplace's Browse/My Listings/Mail, etc. — anything that isn't top-level page nav or CombatPage's switcher keeps this lighter treatment rather than the full gold-gradient CTA look.
- **Page-level framing**: `GameShell.tsx` wraps whichever tab is active in one `AscensionCard title={TAB_TITLES[activeTab]} titleSize="large"` — this is the single page-identity heading (Idling/Equipment/Forge/Market/Shop/Bank/Achievements/LuckyLad). An earlier pass (2026-08-14) instead had each tab page wrap its own content in a second, separate title-only `AscensionCard` — the user flagged this as a redundant nested frame with barely a gap from the real outer one, so don't reintroduce that pattern: a tab page component should never render its own page-identity title card, only genuine in-page section titles (Zone & Monster, Storage, ...) at the `'default'` size.
- **Guardrail — never repaint gameplay-data color coding with this system**: item quality-tier colors, level-diff colors, HP bars, rarity glows (`.super-quality-glow`), tier ember effects, and other established semantic accents (emerald = Fighting/positive state, purple = Ascension Points currency, rose = destructive) are a separate, untouched system. Gold/steel is UI chrome only.
- Full rollout history/reasoning: memory `feedback_ui_visual_style.md` (also records why this reverses an earlier "no gradients" preference — execution/coherence mattered, not gradients-per-se).
