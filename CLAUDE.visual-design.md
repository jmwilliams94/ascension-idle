# Visual Design System

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

**Silver/steel "Ascension" theme (2026-08-14, confirmed app-wide; recolored 2026-08-29 from the original gold/steel palette)** — supersedes the earlier plain-typography/no-gradients look entirely. Cinzel serif headings, gradient silver (`#ffffff→#cbd5e1→#64748b`, held in the same `--ascension-gold-*` CSS vars — renamed the values, not the var names, to avoid a rename sweep across every consumer class) and steel (`#ffffff→#c0d1e3→#7a8b9e`) text, thin gradient-bordered cards, silver-gradient CTA buttons with a hover glow. The 2026-08-29 recolor was a full pivot away from gold — no gold accent remains anywhere in the UI chrome system, including the "selected sub-tab" pattern documented below. Gameplay-data color coding (item tiers, HP bars, the Gold currency's own amber text in `formatGold.ts`, warning/error text, toast/celebration banners like `LevelUpBanner`/`PetToast`) is a separate, untouched system — see the guardrail bullet near the bottom of this file.

**"Prism Obsidian & Light Sweep" chrome pass (2026-08-28)** — reskinned the above; corner/structure unchanged by the 2026-08-29 recolor. Cards/chips/selects moved from rounded corners to chamfered (clip-path-cut) corners; `.btn-gold`/`.btn-gold-active`/`.btn-steel`/`.btn-glow` all gained a glassy top highlight plus a diagonal shine that sweeps across on `:hover` (`::before`/`::after`, needs `overflow: hidden` on the host — see the ember-safe gotcha below for the one exception). `.btn-glow`'s idle background is now `color-mix(in srgb, var(--glow-base) …%, <dark>)` instead of a flat neutral dark, so it reads as "a dark version of its own color" per button. `AscensionCard`'s title also moved from a floating pill-shaped ribbon (overlapping the card's top border, pulsing gold stars either side) to an in-flow header row inside the card's own padding — a plain rule line (`.ascension-card-header-line`, transparent→silver→transparent) on either side of the Cinzel heading, no stars, no absolute positioning. `GameShell.tsx`'s `mt-2 lg:mt-4` on its outer `AscensionCard` (previously compensating for the old ribbon poking up above the frame) was removed along with it — don't re-add spacing compensation for a ribbon that no longer exists.
- **Ember-hosting elements can't be clipped.** `EventEmberBorder` (`src/game/hud/eventEmberBorder.tsx`) renders particles that anchor up to ~56% out from their parent's center — genuinely outside the parent's own box, by the component's own documented contract ("Parent must be `position: relative` and not clip overflow"). Its hosts are `.btn-gold`/`.btn-gold-active` on exactly three call sites (`TabNav.tsx`'s Idling/LuckyLad tabs, `MobileBottomNav.tsx`'s FAB — the inner `<span>`, not the outer borderless `<button>` — and `CombatPage.tsx`'s Events sub-tab) plus `AscensionCard` via its `activeEventColor` prop (`WorldBossCard.tsx`/`GoldDonationCard.tsx` only). All four sites now use the same fix: `EventEmberBorder` renders as a **sibling** of the `.btn-gold`/`.btn-gold-active` button (or `.ascension-card-frame`) inside an outer unclipped `position: relative` wrapper, instead of as a child of it — the button/frame keeps its own `overflow:hidden`/clip-path unconditionally, because the thing that can't tolerate clipping is no longer inside it.
  - An earlier pass (2026-08-16) instead had the three button call sites opt OUT via a `.btn-ember-safe` modifier class added whenever the event-color prop was truthy, reverting `overflow: hidden` to `visible` and unsetting the `::before`/`::after` sweep pseudo-elements' `content`. Removed 2026-08-28 (reported by the user): that also stripped the glass highlight + hover light-sweep every other `.btn-gold` button gets, so e.g. the Idling tab visibly lost its normal chrome exactly while a World Boss fight was making it glow — read as "broken," not "highlighted." `AscensionCard` briefly used the same opt-out approach too, but was fixed first (same day) since its two cards host live embers almost the entire time they're rendered, so the chamfer almost never actually applied.
  Prefer the sibling-wrapper approach over an opt-out modifier class for any future element needing both the ember effect and a clip-path/overflow treatment — `.btn-ember-safe`-style opt-outs read as "the default" only when the exception is genuinely rare, and event states here are not rare enough for that to hold.
  - **`eventBorderTintStyle`'s colored outline ring dropped from two sites, 2026-08-29 (requested by the user)**: `MobileBottomNav.tsx`'s `LuckyNavButton` and `CombatPage.tsx`'s `EventsModeButton` no longer set it — just doubled `EventEmberBorder`'s `count` instead (20→40, 24→48) to compensate for losing the outline's own attention-grabbing effect. `MobileBottomNav.tsx`'s `IdlingNavButton` and `TabNav.tsx`'s Idling/LuckyLad tabs (desktop — the user scoped this change to mobile nav only) still keep the outline. `LuckyNavButton`'s embers also moved off the outer tap target's border onto a small `h-6 w-6` wrapper around just the icon glyph (was anchored to the whole button including the label text below) — same sibling-in-a-relative-wrapper technique, just a much smaller host box.
  - **Mobile Idling FAB is chamfered, not circular, as of 2026-08-29** (requested by the user) — `.ascension-fab-chamfer` (index.css, a `clip-path` sized for the ~56px box) replaces the old `rounded-full` on the inner `.btn-gold`/`.btn-gold-active` span, matching the app's established chamfered corner language instead of a plain circle. Scale the cut distance if this class is ever reused at a meaningfully different box size.

- **Shared primitives, `src/components/ui/`** — use these for any new UI, don't hand-roll card/button/select markup:
  - `AscensionCard` — the gradient-frame card. `title` prop renders an in-flow header row (silver rule line either side of a steel-gradient Cinzel heading, see the Prism Obsidian bullet above); omit it for a plain frame with no title. `titleSize="large"` (2026-08-14, revised same day after the user flagged the first pass — see the Page-level framing bullet below) is `'default'`-sized below `lg` and roughly doubles at `lg`+; used exactly once, by `GameShell.tsx`'s own outer frame, never by an individual tab's own component. Everything else (Zone & Monster, Storage, Achievements, the Equipment gear box's character-name heading, ...) stays `'default'` at every width.
  - `Button` — `variant: 'primary' | 'secondary' | 'danger'`. `primary` = the silver CTA color (the one positive action of a panel — Buy/Confirm/Claim/Fight-style), `.btn-gold` (class name kept, value recolored — see the top-of-file note). `secondary` = steel gradient (Cancel/Back/neutral), `.btn-steel` (2026-08-28 — was a flat `border-slate-700` outline with no theme chrome at all, which read as "unstyled" next to any CTA button beside it; now mirrors `.btn-gold`'s idle-dark/hover-bright-gradient-plus-glow structure on the steel token ramp). `danger` = red outline (Delete/destructive), still a plain `border-rose-700` outline — deliberately outside the silver/steel chrome. No width is set — pass `className="w-full"` etc. yourself.
  - `Select` — wraps a native `<select>` in the same chrome with a custom arrow overlay; preserves per-`<option>` inline `style` colors (e.g. level-diff coloring) unchanged.
- **`TooltipActionPopover`'s button bar is fixed at `w-64`, matching `ItemTooltip`'s own width** (2026-08-28) — without a width of its own it just grew to fit its buttons instead of wrapping, so a long label (Bundle/Open) sharing a row with Bank/Bank All pushed the whole bar wider than the tooltip above it. A 3-action list (Bundle/Open/Claim + two shorter actions) puts the first action on its own full-width row and splits the remaining two across the row below — plain `flex-wrap` won't do this split on its own (each button's text wraps internally before the whole button drops to a new row), so it's explicit: `actions.length > 2` peels off `actions[0]` into its own `w-full` `Button`, the rest render in a `flex-wrap` row beneath. A 1- or 2-action list is unaffected (single row, unchanged).
- **CSS tokens/classes, `src/index.css`** — `.ascension-card-frame`/`.ascension-card-inner`/`.ascension-card-header`/`.ascension-card-header-line` (the card chrome the component wraps), `.ascension-chip-frame`/`.ascension-chip-inner` (compact variant — also what `ItemTooltip`/`TooltipActionPopover`'s button bar use now, 2026-08-28, replacing a plain `border-slate-700` panel), `.text-gradient-gold`/`.text-gradient-steel`, `.btn-gold`/`.btn-steel`, `.text-heading-label` (small-caps Cinzel field label), `.ascension-glow-pulse` (breathing silver glow, `currentColor`-based like the pre-existing `.accent-glow`).
- **Any modal dialog** (`WhatsNewModal`, `OfflineProgressModal`, `SettingsModal`, ...) should use the `ascension-card-frame`/`ascension-card-inner` shell + `Button`, not a hand-rolled `rounded-2xl border border-slate-800 bg-slate-900` panel — several modals were still on the old pattern until an audit pass (2026-08-28) caught them; check any new one against this before assuming it's themed.
- **Any full-screen `fixed inset-0 z-50` modal/overlay must call `useLockBodyScroll()`** (`src/lib/useLockBodyScroll.ts`, 2026-08-28, reported by the user — a touch-drag on a scrollable pane inside SettingsModal's admin Suggestions/Bug Reports queue was scroll-chaining into the game page behind it). This app scrolls at the document/`<body>` level (no fixed-height app-shell-with-internal-scroll), so the hook locks `<body>` itself via `position: fixed` pinned at the current scroll offset (plain `overflow: hidden` on `<body>` isn't reliably respected by iOS Safari for touch scrolling) and restores the exact position when no longer active. Call it unconditionally (`useLockBodyScroll()`) in a component that's only ever mounted by its parent while open; pass the open condition explicitly (`useLockBodyScroll(open)`) in one that stays mounted itself and gates its own return with an internal flag (`ChatOverlay`, `CharacterLoadoutModal`, `VipSettingsModal`, `WorldBossCard`'s repair-alert block, ...) — calling it unconditionally there would lock scroll for the component's entire lifetime, not just while its modal is actually showing. Applied to all 15 real interactive modals as of 2026-08-28 (every `fixed inset-0 z-50` component except `MoneyBagRevealModal`/`SalvageRevealToast`, which are `pointer-events-none` reveal overlays with no interactive/scrollable surface, so nothing to lock against) — any new one needs it too, don't let this regress.
- **`-webkit-tap-highlight-color: transparent` is set globally on `button`/`a`/`[role="button"]`** (2026-08-28) — a plain `<button>` wrapping a rounded child (e.g. `ForgeHub`'s tile buttons around `AscensionCard`) has no border-radius of its own, so mobile WebKit/Chrome's default tap-highlight rectangle can poke past the child's rounded corners. Real precaution, but this was NOT the cause of the ForgeHub gold-gap bug below — don't reach for this fix again for a similar-looking artifact without checking box-model first.
- **`.ascension-card-inner` has explicit `height: 100%`** (2026-08-28, the actual fix for "gold sliver at the bottom of a Forge tile") — `.ascension-card-frame` stretches to match its CSS Grid row's tallest sibling (via `h-full`, e.g. ForgeHub's tiles), but without this rule `.ascension-card-inner` only sizes to its own content. Any row where one tile's description wraps to fewer lines than its row-mate's (Salvage next to Composition, at some viewport widths) left a gap between the shorter inner panel and the taller stretched frame, exposing the frame's own raw gold/steel gradient background as a visible sliver — worse on narrow/mobile widths where text-wrap mismatches between row-mates are more common. `height: 100%` is a no-op wherever the frame's height is auto (nearly every other `AscensionCard` usage), so this is safe globally. Diagnosed by rendering `ForgeHub`'s actual compiled markup+CSS in a headless browser and comparing each tile's frame vs. inner `getBoundingClientRect()` — not visible from reading the JSX/CSS alone.
- **App shell chrome (2026-08-14)** — the page background (`GameShell.tsx`'s root div), header, and mobile bottom nav all use `bg-[...]` with the `--ascension-ink`/`--ascension-ink-soft` tokens (matching `.ascension-card-inner`'s interior) instead of the old plain slate colors. `.ascension-edge-b`/`.ascension-edge-t` — a horizontal silver/steel/silver `border-image` rule (same 3-stop palette as the card frame, rotated 90°) for a straight top/bottom edge on non-boxed elements (header's bottom edge, bottom nav's top edge). `.ascension-chip-frame`/`.ascension-chip-inner` — compact gradient-border-via-padding pill, same technique as the card frame but smaller radius and no drop shadow, for small HUD elements (ExpBar, PlayersOnlineHud, ChatButton, header's Switch Character/Settings/Sign out buttons); add `.is-interactive` alongside `.ascension-chip-frame` on actual buttons for a brighter hover gradient — omit it on plain info pills so they don't read as clickable.
- **Top-level nav buttons** — `TabNav.tsx`'s 8-tab desktop grid and `MobileBottomNav.tsx`'s circular Idling FAB use `.btn-gold`/`.btn-gold-active` (2026-08-16, supersedes the plain amber-border toggle these used to have) — `.btn-gold` for the idle state, `.btn-gold-active` (index.css — the permanently-lit variant of `.btn-gold`'s own `:hover` gradient, applied instead of `.btn-gold`, never alongside it) for whichever tab is currently open. `MobileBottomNav.tsx`'s four side tabs (Equip/LuckyLad/Tavern/Achiev.) and the Tavern rollup's own collapsed button do NOT use this — see the borderless-pill entry below.
- **`MobileBottomNav.tsx`'s four side tabs are borderless, not boxed** (2026-08-28 redesign, requested by the user — the old per-button `.btn-gold`/`.btn-gold-active` box made all five bar items read as equally-weighted boxed buttons, competing with the Idling FAB instead of deferring to it). The outer `<button>` is a plain unstyled tap target; only the active tab's icon+label sits inside a small `.nav-pill-active` pill (index.css — same gradient/glow as `.btn-gold-active` but no border, sized to hug its own content via an inner `<span>` rather than stretching edge-to-edge). Idle tabs get no background at all, just `text-slate-400`. This also retired the old `outerCorner` prop on `NavButton` (previously matched a boxed button's corner to the bar's own `rounded-b-[3rem]` mask) — moot now that idle buttons have no box, and the active pill sits well clear of the bar's physical edge. The row's `px-2` inset (keeps tap targets off the phone's physical screen edge) is unrelated and unchanged — don't reintroduce edge-flush buttons when touching this again.
- **CombatPage's Hunting/Mining/Events switcher also uses `.btn-gold`/`.btn-gold-active`** (2026-08-16, same pass as the top-level nav restyle, applied here on a follow-up request) — Mining stays `disabled` rather than getting its own dimmed-opacity wrapper, relying on `.btn-gold:disabled`'s built-in dimming like every other disabled button in the app.
- **Active/selected toggle state elsewhere** (other in-page sub-tab pickers — not a `Button`, since `Button` has no notion of a selected state): a lighter silver accent (`border-slate-300 bg-slate-300/10 text-slate-100`, unselected branch `border-slate-700 text-slate-300 hover:border-slate-400/50` or the migrated `.ascension-chip-inner ... hover:text-slate-100`), not the app's old sky-500 accent or (pre-2026-08-29) gold `border-amber-400 bg-amber-500/10 text-amber-300`. Achievements' Character/Account/Pets, Bank's Character/Account, Enchantress' Enchant/Bless, GearScoreLeaderboard's class filter, Marketplace's Browse/My Listings/Mail + currency/duration toggles, MasterForge's Quality/Level, Shop's category tiles, BankSquares' Deposit/Withdraw + Individual/Scroll + gem type/tier pickers, MobileBottomNav's Tavern rollup, SettingsModal's sidebar, VipSettingsModal's priority toggle, InventoryPanel's compare toggle — anything that isn't top-level page nav or CombatPage's switcher keeps this lighter treatment rather than the full CTA look.
- **Page-level framing**: `GameShell.tsx` wraps whichever tab is active in one `AscensionCard title={TAB_TITLES[activeTab]} titleSize="large"` — this is the single page-identity heading (Idling/Equipment/Forge/Market/Shop/Bank/Achievements/LuckyLad). An earlier pass (2026-08-14) instead had each tab page wrap its own content in a second, separate title-only `AscensionCard` — the user flagged this as a redundant nested frame with barely a gap from the real outer one, so don't reintroduce that pattern: a tab page component should never render its own page-identity title card, only genuine in-page section titles (Zone & Monster, Storage, ...) at the `'default'` size.
- **Guardrail — never repaint gameplay-data color coding with this system**: item quality-tier colors, level-diff colors, HP bars, rarity glows (`.super-quality-glow`), tier ember effects, and other established semantic accents (emerald = Fighting/positive state, purple = Ascension Points currency, rose = destructive) are a separate, untouched system. Gold/steel is UI chrome only.
- **Tinted chip/card frames (2026-08-29)** — `.ascension-chip-frame.is-tinted` / `.ascension-card-frame.is-tinted` (index.css) recolor the chamfered gradient frame away from the default silver/steel using a single `--ascension-tint` CSS custom property (a hex color, set inline per consumer), the three gradient stops derived via `color-mix` — same parameterization technique `.btn-glow` already used for `--glow-bright/-base/-dark`. For a modal, `BankActionModal` takes this as a `tint` prop (applies `is-tinted` + the var to both the outer frame and the close button's chip) plus an optional `widthClassName` (default `max-w-sm`, override for content-dense panels). Current consumers: `VipStatusHud`/`VipSettingsModal` (violet `#8b5cf6` — deliberately not the app's true `purple`, which is Ascension Points' own established currency color, see the guardrail below), `GlobalAnnouncementTicker` (green `#22c55e`). Reuse this instead of hand-rolling a one-off colored border/background for any future semantic-colored badge or modal.
- **Item icon tiles use a rounded gradient-border frame, not the chamfered card/chip corners (2026-09-01)** — `.item-quality-frame`/`.item-quality-frame-inner` (index.css), the one deliberate exception to the app-wide chamfer: every other bordered container (cards, chips, the FAB) keeps cut corners, but gear/material tiles specifically got curved corners instead, design-reviewed live in Settings > Item Effects (`ItemEffectGallery.tsx`) before rollout. Same gradient-border-via-padding technique as `.ascension-chip-frame`, parameterized by its own `--item-tier-color` custom property (not `--ascension-tint` — kept as a separate system per the gameplay-color guardrail below) and defaulting to a neutral steel gray so Normal-quality/colorless tiles still get the metallic frame look. Replaces the old flat `border-2` + inline `borderColor: qualityColor` in all three places that rendered it: `InventorySlot.tsx` (the shared tile behind Inventory/Forge/Bank/Loot Holding), `EquipmentSlot.tsx` (paper-doll, a separate bespoke component — only applied when `filled`, an empty slot keeps its plain dashed placeholder), and `dragDrop.tsx`'s floating drag ghost.
- **`WorldBossLeaderboardModal`/`GoldDonationLeaderboardModal` now use `BankActionModal`** (2026-08-29 — they were still on the old hand-rolled `rounded-2xl border-slate-800 bg-slate-900` pattern the modal-shell audit bullet above was supposed to catch, missed because they predate that audit). `GoldDonationLeaderboardModal` is a direct copy of `WorldBossLeaderboardModal` (see its own top-of-file comment) — keep them in sync, same as the `resolve-combat` duplication rule in the root `CLAUDE.md`. Their `RANK_ACCENT`/self-row amber (#1/You highlighting) is a medal-color convention, not leftover gold theme — deliberately not touched by the 2026-08-29 silver recolor, same category as `GearScoreLeaderboardPanel`'s "You" row.
- **GameShell's wordmark accents are a plain grey fade-line, not stars** (2026-08-29, replacing the pulsing gold `✦` glyphs `.ascension-glow-pulse` used to drive) — `<span className="h-px w-6 shrink-0 bg-gradient-to-r/-l from-transparent to-slate-500 sm:w-8" />` flanking "ASCENSION IDLE", no animation. If a future ask wants the wordmark decorated again, this is the current baseline to modify, not the old star treatment.
