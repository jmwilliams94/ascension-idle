# Visual Design System

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

**Gold/steel "Ascension" theme (2026-08-14, confirmed app-wide)** — supersedes the earlier plain-typography/no-gradients look entirely. Cinzel serif headings, gradient gold (`#fff3a1→#d4af37→#997a15`) and steel (`#ffffff→#c0d1e3→#7a8b9e`) text, thin gradient-bordered "ribbon" cards, gold-gradient CTA buttons with a hover glow.

- **Shared primitives, `src/components/ui/`** — use these for any new UI, don't hand-roll card/button/select markup:
  - `AscensionCard` — the gradient-frame card. `title` prop renders a floating ribbon (pulsing gold stars + steel-gradient Cinzel heading); omit it for a plain frame with no ribbon. `titleSize="large"` (2026-08-14, revised same day after the user flagged the first pass — see the Page-level framing bullet below) is `'default'`-sized below `lg` and roughly doubles at `lg`+; used exactly once, by `GameShell.tsx`'s own outer frame, never by an individual tab's own component. Everything else (Zone & Monster, Storage, Achievements, the Equipment gear box's character-name heading, ...) stays `'default'` at every width.
  - `Button` — `variant: 'primary' | 'secondary' | 'danger'`. `primary` = gold CTA (the one positive action of a panel — Buy/Confirm/Claim/Fight-style), `.btn-gold`. `secondary` = steel gradient (Cancel/Back/neutral), `.btn-steel` (2026-08-28 — was a flat `border-slate-700` outline with no theme chrome at all, which read as "unstyled" next to any gold button beside it; now mirrors `.btn-gold`'s idle-dark/hover-bright-gradient-plus-glow structure on the steel token ramp). `danger` = red outline (Delete/destructive), still a plain `border-rose-700` outline — deliberately outside the gold/steel chrome. No width is set — pass `className="w-full"` etc. yourself.
  - `Select` — wraps a native `<select>` in the same chrome with a custom arrow overlay; preserves per-`<option>` inline `style` colors (e.g. level-diff coloring) unchanged.
- **CSS tokens/classes, `src/index.css`** — `.ascension-card-frame`/`.ascension-card-inner`/`.ascension-card-ribbon` (the card chrome the component wraps), `.ascension-chip-frame`/`.ascension-chip-inner` (compact variant — also what `ItemTooltip`/`TooltipActionPopover`'s button bar use now, 2026-08-28, replacing a plain `border-slate-700` panel), `.text-gradient-gold`/`.text-gradient-steel`, `.btn-gold`/`.btn-steel`, `.text-heading-label` (small-caps Cinzel field label), `.ascension-glow-pulse` (breathing gold glow, `currentColor`-based like the pre-existing `.accent-glow`).
- **Any modal dialog** (`WhatsNewModal`, `OfflineProgressModal`, `SettingsModal`, ...) should use the `ascension-card-frame`/`ascension-card-inner` shell + `Button`, not a hand-rolled `rounded-2xl border border-slate-800 bg-slate-900` panel — several modals were still on the old pattern until an audit pass (2026-08-28) caught them; check any new one against this before assuming it's themed.
- **`-webkit-tap-highlight-color: transparent` is set globally on `button`/`a`/`[role="button"]`** (2026-08-28) — a plain `<button>` wrapping a rounded child (e.g. `ForgeHub`'s tile buttons around `AscensionCard`) has no border-radius of its own, so mobile WebKit/Chrome's default tap-highlight rectangle can poke past the child's rounded corners. Real precaution, but this was NOT the cause of the ForgeHub gold-gap bug below — don't reach for this fix again for a similar-looking artifact without checking box-model first.
- **`.ascension-card-inner` has explicit `height: 100%`** (2026-08-28, the actual fix for "gold sliver at the bottom of a Forge tile") — `.ascension-card-frame` stretches to match its CSS Grid row's tallest sibling (via `h-full`, e.g. ForgeHub's tiles), but without this rule `.ascension-card-inner` only sizes to its own content. Any row where one tile's description wraps to fewer lines than its row-mate's (Salvage next to Composition, at some viewport widths) left a gap between the shorter inner panel and the taller stretched frame, exposing the frame's own raw gold/steel gradient background as a visible sliver — worse on narrow/mobile widths where text-wrap mismatches between row-mates are more common. `height: 100%` is a no-op wherever the frame's height is auto (nearly every other `AscensionCard` usage), so this is safe globally. Diagnosed by rendering `ForgeHub`'s actual compiled markup+CSS in a headless browser and comparing each tile's frame vs. inner `getBoundingClientRect()` — not visible from reading the JSX/CSS alone.
- **App shell chrome (2026-08-14)** — the page background (`GameShell.tsx`'s root div), header, and mobile bottom nav all use `bg-[...]` with the `--ascension-ink`/`--ascension-ink-soft` tokens (matching `.ascension-card-inner`'s interior) instead of the old plain slate colors. `.ascension-edge-b`/`.ascension-edge-t` — a horizontal gold/steel/gold `border-image` rule (same 3-stop palette as the card frame, rotated 90°) for a straight top/bottom edge on non-boxed elements (header's bottom edge, bottom nav's top edge). `.ascension-chip-frame`/`.ascension-chip-inner` — compact gradient-border-via-padding pill, same technique as the card frame but smaller radius and no drop shadow, for small HUD elements (ExpBar, PlayersOnlineHud, ChatButton, header's Switch Character/Settings/Sign out buttons); add `.is-interactive` alongside `.ascension-chip-frame` on actual buttons for a brighter hover gradient — omit it on plain info pills so they don't read as clickable.
- **Top-level nav buttons** (`TabNav.tsx`'s 8-tab desktop grid, `MobileBottomNav.tsx`'s bar including the circular Idling button and the Tavern rollup) use the same `.btn-gold`/`.btn-gold-active` treatment as the `Button` primary/Fight-style CTA (2026-08-16, supersedes the plain amber-border toggle these used to have) — `.btn-gold` for the idle state, `.btn-gold-active` (index.css — the permanently-lit variant of `.btn-gold`'s own `:hover` gradient, applied instead of `.btn-gold`, never alongside it) for whichever tab is currently open.
- **CombatPage's Hunting/Mining/Events switcher also uses `.btn-gold`/`.btn-gold-active`** (2026-08-16, same pass as the top-level nav restyle, applied here on a follow-up request) — Mining stays `disabled` rather than getting its own dimmed-opacity wrapper, relying on `.btn-gold:disabled`'s built-in dimming like every other disabled button in the app.
- **Active/selected toggle state elsewhere** (other in-page sub-tab pickers — not a `Button`, since `Button` has no notion of a selected state): still the older gold accent (`border-amber-400 bg-amber-500/10 text-amber-300`), not the app's old sky-500 accent. Achievements' Character/Account/Pets, Marketplace's Browse/My Listings/Mail, etc. — anything that isn't top-level page nav or CombatPage's switcher keeps this lighter treatment rather than the full gold-gradient CTA look.
- **Page-level framing**: `GameShell.tsx` wraps whichever tab is active in one `AscensionCard title={TAB_TITLES[activeTab]} titleSize="large"` — this is the single page-identity heading (Idling/Equipment/Forge/Market/Shop/Bank/Achievements/LuckyLad). An earlier pass (2026-08-14) instead had each tab page wrap its own content in a second, separate title-only `AscensionCard` — the user flagged this as a redundant nested frame with barely a gap from the real outer one, so don't reintroduce that pattern: a tab page component should never render its own page-identity title card, only genuine in-page section titles (Zone & Monster, Storage, ...) at the `'default'` size.
- **Guardrail — never repaint gameplay-data color coding with this system**: item quality-tier colors, level-diff colors, HP bars, rarity glows (`.super-quality-glow`), tier ember effects, and other established semantic accents (emerald = Fighting/positive state, purple = Ascension Points currency, rose = destructive) are a separate, untouched system. Gold/steel is UI chrome only.
- Full rollout history/reasoning: memory `feedback_ui_visual_style.md` (also records why this reverses an earlier "no gradients" preference — execution/coherence mattered, not gradients-per-se).
