# PWA & Mobile

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

- **PWA installability**: `vite-plugin-pwa` (`vite.config.ts`) generates manifest + Workbox service worker; `registerSW({ immediate: true, onNeedRefresh })` in `main.tsx`. **Scope: installable + static-asset caching only — not full offline play.** No `runtimeCaching` for Supabase API/game state (deliberate — conflicts with the server-authoritative-currency trust model and debounced autosave). Distinct from the AFK/offline-progress simulator, which needs a live connection on return.
- **Resume detection** (for the offline-progress "welcome back" check) uses **three independent triggers**, since `visibilitychange` alone is unreliable for a Home-Screen-installed PWA resuming on mobile (a known WebKit/standalone-PWA quirk): `visibilitychange`→`'visible'`, `window`'s `focus` event, and a **heartbeat drift detector** — a `setInterval` ticking every 3s (`HEARTBEAT_INTERVAL_MS`) compares expected vs actual fire time; a gap over `RESUME_GAP_THRESHOLD_MS` (10s) means the app was backgrounded and triggers the same resume check, independent of whether the OS correctly reports visibility at all. All three funnel into one `checkOfflineProgressOnResume` helper (guards against firing while a fresh, undismissed result is already pending). Away-time for the "show a spinner or not" decision (`GameShell.tsx`) comes from `hiddenAt` (set on a real `visibilitychange`→hidden) when available, else falls back to `lastAliveAt` (the heartbeat's own last-tick timestamp) rather than assuming an unknown gap is real — fixes the `focus` trigger firing on a plain desktop OS-level window switch (alt-tab away and back, no tab-visibility change at all), which previously always flashed the "Calculating…" spinner with nothing to show for it.
- **Orientation locked portrait** (`orientation: 'portrait-primary'` in manifest).
- **Update flow**: prompt-based (2026-08-08, supersedes an earlier silent `autoUpdate` flow that applied on the player's next natural reload with no UI). `registerType: 'prompt'` — a new build installs in the background as before, but now `main.tsx`'s `onNeedRefresh` callback flips `useAppUpdateStore.needRefresh` true, and `UpdateBanner.tsx` (rendered at the `App.tsx` root, outside `AuthGate`, so it's visible even on the login screen) shows a fixed top banner with a "Refresh" button. Refresh calls the store's `applyUpdate`, which invokes `registerSW`'s own returned `updateSW(true)` — activates the waiting service worker and reloads the page. No dismiss button (nothing to opt out of, only defer — closing the tab still applies it next launch). Independent of the existing `last_seen_version` "What's New" modal, which is a separate check.
- **App icons**: `public/pwa-icons/` (`pwa-192.png`, `pwa-512.png`, `pwa-maskable-512.png`), a gold "A" mark on near-black navy (`theme_color`/`background_color` = `#0b0f19`). **Flagged, not fixed**: `favicon.svg` (browser-tab icon) still shows the old purple lightning-bolt mark — visibly disagrees with the installed-PWA icon. Revisit if/when vector art for the new logo shows up.
- **Forge touch drag-and-drop**: custom Pointer Events system (`src/components/dragDropContext.ts` for context/hook, `dragDrop.tsx` for `DragDropProvider`/`DraggableInventorySlot`) works for mouse/touch/pen — a floating ghost tile follows the pointer, drop targets are wrapper elements with `data-drop-zone="<key>"` (generalized from the earlier Forge-only `data-forge-drop` name; Forge's own keys `"upgrade"`/`"fuel-0"`/`"fuel-1"` unchanged), resolved via `document.elementFromPoint` at release. `InventoryPanel`'s `onTileDrop` prop opts an instance in (Forge and Warehouse both use it now — Warehouse was migrated off native HTML5 DnD to this same system, so touch now works both directions there too; `InventoryPanel`'s old `nativeDraggable` prop is gone entirely).
- **Mobile-responsive layout**: `SLOT_SIZE_CLASS`(`InventorySlot.tsx`)/`InventoryPanel`'s `gridColsClass` are responsive (`h-14 w-14`/3.5rem below `lg`, `h-16 w-16`/4rem at `lg`+) plus a defensive `overflow-x-auto` wrapper — fixed once in the shared component so every embedding (Forge/Shop/Warehouse/Combat) benefits. `CombatPage.tsx` has an entirely separate mobile layout (`lg:hidden`/`hidden lg:grid`, not a reflow), action-first order: monster HP+Fight/Stop → your HP+Consumable → Zone/Monster picker → Inventory (collapsed). `EquipmentPanel.tsx`'s paper-doll and `ForgePanel.tsx`'s Upgrade Slot/Result Preview row are both responsive (stack vertically below `lg`).
- **`TabNav.tsx` is desktop-only** (`hidden lg:grid`, `grid-cols-8`). Mobile uses **`MobileBottomNav.tsx`** (`lg:hidden`, `fixed inset-x-0 bottom-0`, `env(safe-area-inset-bottom)` padding): left-to-right **Equip**, **Lucky**, **Idling** (center, larger circular button, navigation-only — doesn't itself start/stop combat), **Tavern**, **Achieve**. **Idling** (2026-08-14, renamed from "Fighting"/live Fight-Idle status — the old per-weapon-family dynamic icon, `getWeaponIcon`/`WEAPON_FAMILY_ICONS`, is gone) shows a static hourglass icon and always reads "Idling", matching `GameShell.tsx`'s `TAB_TITLES.combat` page heading; `TabNav.tsx`'s desktop Combat button is now just a plain `TabButton` too, no separate `CombatTabButton`. **Tavern** (renamed from "Town", 2026-08-14) is a speed-dial rollup (not a real tab — `TabId` has no `'tavern'` value) containing Market/Bank/Shop/Forge — tapping toggles a stack rising above the button (`framer-motion` `AnimatePresence`, ~180ms fade+rise), collapses on pick/re-tap/outside-pointerdown. Tavern highlights active whenever the current tab is one of its 4. `GameShell.tsx`'s `<main>` has `pb-24` below `lg` (unchanged at `lg`+) so content isn't covered.
  - Icons: real PNG art for every nav tab as of 2026-08-14 (Idling/Equipment/Forge/Market/Shop/Bank/Achievements/LuckyLad/Tavern, `public/nav-icons/`, `public/lucky-icons/`) — no more emoji placeholders. Nav icon art pipeline: source images trimmed then `sharp` `resize(320, 320, { fit: 'cover' })` to a square PNG (same convention `public/item-icons/` already uses), no padding. All `public/`-served icon URLs append `?v=${APP_VERSION}` (`navIcons.ts`'s `iconUrl` helper) to cache-bust — see that file's own doc comment for why (unhashed `public/` filenames + GitHub Pages/Cloudflare's 4h `Cache-Control` otherwise leave already-cached players stuck on old art after an in-place art swap).
- **Lucky (LuckyLad) — Stage 1 implemented.** `TabId` has `'lucky'`. A free ticket every **4 hours** (lowered from 6, requested by the user, 2026-08-21 — `interval '4 hours'` server-side in `draw_lucky_ticket`, `LUCKY_FREE_TICKET_COOLDOWN_MS` client-side in `useLuckyStore.ts`), plus uncapped paid extra attempts at flat **20 AP** each (or 1 Lottery Ticket). 9 face-down cards; picking one reveals its reward, the other 8 then flip to show what they would have been (informational only). **Bulk draw** (2026-08-22, requested by the user): a third "Open All 9" button, flat **160 AP** (8x the single-card AP cost — pay for 9, priced as 8), where all 9 cards grant real independent rewards instead of just one — opened one at a time at the player's own pace, no per-card payment.
  - **Security**: `draw_lucky_ticket(p_character_id, p_card_index, p_use_ticket default false)` (migration `20260803020000_add_lucky_ticket.sql`, current full body in `20260821080000_lucky_comet_box_reward.sql`) is a single atomic `SECURITY DEFINER` RPC — the client commits to a card index **blind** (no board data ever sent or exists client-side before the call); the RPC checks eligibility, rolls all 9 rewards server-side, grants the one at `card_index`, and only then returns the full board. `characters.lucky_free_ticket_claimed_at` is the only new column, server-authoritative, excluded from autosave. **Bulk**: `draw_lucky_ticket_bulk(p_character_id)` (migration `20260822000000_lucky_bulk_draw.sql`) is the same pattern but grants all 9 rolled cards at once (charging 160 AP up front, room-checked for up to 9 slots before anything is charged) — the client-side one-at-a-time reveal is purely a local animation gate over an already-fully-decided, already-paid-for board, not a new blind-pick surface.
  - **Reward pool** (Stage 1, deliberately narrow): 10 gold tiers (25/50/100/200/400/750/1500/3000/6000/12000, PLACEHOLDER), plus Comet, Fallen Star, Comet Scroll, Fallen Star Scroll, Money Bag/Gem Bag/Composition Stone tiers, per-gem-type Tempered/Ascended gem kinds, three hyper-rare gear kinds — and **Comet Box** (2026-08-21, requested by the user): a flat, instant **+100 Comets**, distinct from the plain 'comet' kind's +1. Weight **4.0** (2026-08-23, set to match Fallen Star's own weight exactly, requested by the user; funded by trimming Class 1 Money Bag's own weight down to 12.3 so the table still sums to exactly 100). Each of the 9 cards independently rolls from one shared weighted table (`pick_lucky_reward()`, weights sum to 100, current full body in `20260823000000_fix_lucky_gem_split_regression.sql`) — **not** 9-unique-prizes, duplicates across cards are legitimate. Low gold tiers dominate; Fallen Star Scroll is rarest (weight 0.4, 1-in-250/card). **Deliberately deferred, not invented**: hyper-rare Radiant/Ascended gear rewards beyond the three already implemented, a new "bonus consumable" category (buffs to rare-drop chance — nothing like it exists), Gems beyond the 4 already coded (see `CLAUDE.gear-and-forge.md`). Revisit once that content exists.
  - **Gotcha, bit once already**: the per-gem-type kind split (`gem_tempered_<id>`/`gem_ascended_<id>`, not the old bare `gem_tempered`/`gem_ascended`) must be preserved every time `pick_lucky_reward()` is redefined — `20260821080000_lucky_comet_box_reward.sql` accidentally redefined it from a stale pre-split copy, which silently broke card reveals (a card with the bare kind had no matching client-side case, so it never flipped) and silently dropped the reward entirely if it was the card actually granted. Fixed in `20260823000000_fix_lucky_gem_split_regression.sql`. When editing this function's weight table again, copy from the current migration, not an old one.
  - **Client** (`LuckyPanel.tsx`, `useLuckyStore.ts`): tapping a card arms it locally (no network call), reveals Confirm/Cancel showing cost ("Free" or "20 AP") before `draw_lucky_ticket` actually fires. On response: won card flips first (amber "WON" badge), other 8 flip staggered; gold/currency/AP set directly from the RPC's authoritative response (absolute sets). A won `comet_box` additionally fires `useMoneyBagRevealStore`'s center-screen reveal card (same one Money Bag/Gem Bag opens use, styled with the Comet icon and "+100 Comets") straight from `LuckyPanel.tsx`'s `handleOpen`, since the grant is instant with no separate "open" step. "Draw Again" resets to 9 face-down. Free-ticket countdown re-renders every 30s via a `Date.now()`-in-state pattern (not called directly in render body, satisfies `react-hooks/purity`).
  - **Announcements**: winning a `comet_box` also inserts a `lucky_comet_box` row into `global_announcements` (same "at least as rare as Comet Scroll" threshold every other announced LL kind uses — Comet Box's weight of 4.0 still clears it), shown with the Comet icon in `GlobalAnnouncementTicker.tsx`.
  - Real mascot art: `public/lucky-icons/luckylad.png` (mascot + nav icon), `chest-closed.png` (face-down card), `chest-open.png` (reveal backdrop, reward icon overlays as a corner badge).
