# Feedback & Planning (Settings menu)

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

Three sections inside `SettingsModal.tsx` (gear icon, not top-level `TabNav`/`MobileBottomNav` tabs — these are meta/support pages, not gameplay), all visible to every player. All admin gating uses `public.is_admin()`, a `SECURITY DEFINER` SQL helper (`select auth.uid() = (select id from auth.users where email = '<admin>')`) — **required** for any RLS policy that needs to check admin status: a plain RLS `USING` clause runs under the querying role's own privileges (`authenticated`), which has no `SELECT` grant on `auth.users` in this project, so an inline `auth.users` lookup in a policy throws a permission error instead of evaluating false (hit `bug_reports`' original admin policy — fixed in `20260821020000_fix_bug_reports_admin_rls.sql`, which added `is_admin()`). Client-side `useIsAdmin()` (hardcoded email check) is cosmetic everywhere here too, same as every other admin gate in this project.

- **Plans** (`PlanPanel.tsx`/`usePlanStore.ts`, `plan_items` table): a public read-only roadmap list. Only the admin can add/remove/reorder (`admin_add_plan`/`admin_remove_plan`/`admin_reorder_plans`). Reordering is real drag-and-drop, admin-only — a small self-contained Pointer Events implementation (not the Forge/Warehouse grid drag system, which is built around fixed square item-slot drop zones): reads each row's live `getBoundingClientRect()` on move (not `elementFromPoint`, small list so no lag concern), live-reorders via a `framer-motion` `layout` animation, persists the full ordered id array once on drop (`admin_reorder_plans` rewrites every row's `position` to match array index). Supersedes an earlier "To-Do" board that was fully dropped (table + RPCs) when Suggestions first shipped, then Plans was re-added after the user asked for it back with reordering.
- **Suggestions** (`SuggestionsPanel.tsx`/`useSuggestionStore.ts`, `suggestions` table) and **Bug Reports** (`BugReportPanel.tsx`/`useBugReportStore.ts`, `bug_reports` table): nearly-identical, deliberately kept as separate tables. Any player submits one against their active character and sees their own history (`character_name` is a snapshot at submit time — `characters` has no cross-account SELECT policy, so the admin's "view everyone's" query needs the name baked in). Only the admin sees every row across every account (additive RLS policy) and closes one out with a comment — Bug Reports as **Fixed**/**Rewarded**, Suggestions as **Implemented**/**Rejected** — optionally attaching a **currency-only** reward (Comet/Fallen Star/their Scrolls/Lottery Ticket/Ascension Points — deliberately no gear/weapons, unlike Admin Mail) delivered through the existing `mail` table (`reason: 'bug_report_reward' | 'suggestion_reward'`).
- **Reply threads**: one shared `report_replies` table backs both Suggestions and Bug Reports via two nullable FKs (`bug_report_id`/`suggestion_id`) + an XOR check constraint — same pattern `mail`'s `item_id`/`currency_type` pair already uses, avoiding a duplicated table+RLS+RPC set for what's genuinely one feature attached to two parents. Shared `ReportReplyThread.tsx` + `useReportReplyStore.ts`, rendered inside every expandable row (open, resolved, and the player's own history) regardless of status — either side can keep talking after a report is already closed. Closing a report/suggestion also inserts the closing comment into the thread (in addition to the existing `admin_comment` summary field), so the conversation reads end-to-end. **Landmine**: `ReportReplyThread`'s replies selector must never fall back to a bare `[] `/`{}` literal (e.g. `state.repliesByParentId[id] ?? []`) — allocates a new reference every render while the key is unset, which crashes the whole app to a blank screen (React error #185) since Zustand's `useSyncExternalStore` subscription compares snapshots by reference. Fixed with a stable module-level `EMPTY_REPLIES` constant; same pitfall as the `.filter()`-in-selector case noted in `CLAUDE.md`'s cross-cutting gotchas — any inline array/object literal in a selector body is the bug, not just method chains.
