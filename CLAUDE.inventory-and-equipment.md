# Inventory, Equipment & Consumables

> Part of the split `CLAUDE.md` docs — see [`CLAUDE.md`](CLAUDE.md) for git/versioning workflow and cross-cutting gotchas.

## Inventory

- A single fixed **40-cell grid** (`INVENTORY_SLOT_CAP` in `useInventoryStore.ts`), always renders all 40 cells (empty ones dimmed/unclickable). `InventorySlot` is a dumb/presentational per-cell component. `InventoryPanel` renders as multiple independent instances across pages (Combat page at `columns={5}`, Forge at `columns={8}`, Equipment tab, Warehouse/Bank, Shop, Marketplace) — each has independent local state (e.g. Forge's `reservedItemIds` reservation only affects that instance's own grid rendering, not others'; not shared globally, a known accepted tradeoff). `columns` prop must be spelled out literally (5 or 8) in the component so Tailwind's class scanner picks it up — do not template the class name dynamically. The real scaling-cap-by-level model (30→40 via bag upgrades, maxing ~level 67) is **not built** — every character currently treated as already at max 40.
- **Equipped, listed, and banked gear all leave Inventory entirely** — filtered out of every `InventoryPanel`'s `visibleItems` (checks `isEquipped`, `isListed`, and bank `location`) and don't count toward the 40-slot cap. Unequipping/delisting/withdrawing brings it straight back (no extra bookkeeping, since it's just a filter).
- A potion stack or a non-zero Composition stone tier each occupies a slot exactly like gear (`occupiedSlotCount` sums gear + stones + potion stacks + Comet/Fallen-Star loose units + Scroll counts). Potion/stone tiles show a plain count badge (no quality tint). Forge drag-and-drop: gear → Upgrade Slot, gear+stones → Fuel slots; potions are never dragged into Forge.
- **`GearEquipPopover`** (Inventory grid only, via `equipPopoverEnabled` prop, Combat page + Equipment tab): pressing a gear tile opens a popover with the tile's normal `ItemTooltip` content plus **Equip** and (if something's already equipped in that slot) **Compare** buttons (side-by-side ≥640px, stacked below). Hover/long-press tooltip peek still works independently and simultaneously (not either/or) — except the one tile whose popover is currently open, which suppresses its own peek to avoid visual overlap (`isPopoverOpenForSelection` helper in `InventoryPanel.tsx`, mirrored in `LootHoldingCard.tsx`). Scope is deliberately narrow — Forge/Warehouse/Shop/Marketplace tiles keep their existing click behavior (drag source / sell-select / listing source), unaffected.
- **Universal hover tooltip** (`ItemTooltip.tsx`, dark card, quality-colored title, info lines, stats block) shown via `InventorySlot`'s `tooltip` prop, built by shared functions: `buildGearTooltip` (`equipmentBonus.ts`), `buildStoneTooltip`/`buildMeteorTooltip`/etc. (`forgeCosts.ts`), potions built inline. Shared shape `ItemTooltipData` lives in `src/game/items/itemTooltip.ts` (dependency-free, avoids a circular import between `equipmentBonus.ts` and `forgeCosts.ts`). Works everywhere a tile renders (Inventory, Forge slots, Equipment paper-doll). Native `title` popup is suppressed when `tooltip` is supplied. Optional `icon`/`iconSrc`/`iconColor` fields render a bordered icon box beside the title+lines+stats column (icon spans the full card height as its own left column) when set.
  - **Per-line colors** (`ItemTooltipData.lines`/`stats`, 2026-08-13): each entry is a plain string (block's own default — slate for `lines`, sky blue for `stats`, `DEFAULT_STAT_COLOR` in `itemTooltip.ts`) or `{ text, color }` to override just that one line (`TooltipLine` type). `bonusStats` (Composition's purple "Bonus:" lines), `enchantLine` (Enchanted HP's muted gold), and `blessLine` (Bless's soft orange, `BLESS_COLOR`) are separate fields with their own hardcoded colors in `ItemTooltip.tsx`, unaffected by this per-line mechanism — see `CLAUDE.gear-and-forge.md` for what feeds these.
  - **Gear tooltip line order** (`buildGearTooltip`, reordered 2026-08-13 — supersedes the earlier layout where all base stats sat in a separately-bordered block below Lvl/Class/Sockets): everything now flows in one un-bordered block — **Lvl → Class → base stats (white: Physical Defense/Dodge, then blue: Physical/Magic Attack, Magic Defense, Dexterity) → Sockets** (header + per-socket lines, white header / soft-green filled-socket description / default-slate "Empty"). Base stats moved from the old `stats` field into `lines` for this — `buildStatTooltipLines` (`equipmentBonus.ts`) now explicitly colors every entry (white via `WHITE_STAT_KEYS`, else `DEFAULT_STAT_COLOR`) and partitions white-first/blue-second, since `lines`' own default (slate) differs from `stats`' own default (blue) and base_stats' raw JSON key order isn't a reliable ordering signal. `buildGearTooltip` no longer populates `stats` at all (still used by non-gear tooltips — stones/gems/currency, `forgeCosts.ts`/`gemTypes.ts`). A second, separately-bordered block still renders below for Composition's `bonusStats` (purple), `enchantLine` (Enchanted HP, gold), and `blessLine` (Bless, orange) — `ItemTooltip.tsx`'s `hasBonusBlock` triggers that border on any of those three being present, not on `stats.length` (which is now always empty for gear).
  - **Positioning**: `HoverTooltip.tsx` portals into `document.body` via `createPortal`, positions with `position: fixed` from `getBoundingClientRect()` — immune to ancestor `overflow` clipping. Clamps horizontally to viewport edges (assumes `ItemTooltip`'s fixed `w-52`/208px), flips below the trigger if <~160px room above (heuristic, not exact).
  - **Touch fallback**: long-press (not tap-to-toggle, to avoid colliding with tap-to-select or drag-and-drop). `pointerdown` (touch only) arms a `450ms` timer; movement >`10px` cancels it; on fire, tooltip shows until `pointerup`/`pointercancel`; the following click is swallowed via capture-phase `onClickCapture`; `onContextMenu` suppressed. Real `<img>` icons on iOS Safari need an additional blanket CSS rule (`img { -webkit-touch-callout: none; -webkit-user-drag: none; user-select: none; }` in `index.css`) since WebKit's own long-press-image callout isn't reachable via JS `contextmenu` prevention.
- **Full-inventory behavior**: roll (`useInventoryStore.rollItemDrop`) and grant (`grantItemDrop`) happen at kill time. `grantItemDrop` takes an `interactive` flag — live combat always `true`, offline simulator always `false`. If the combined slot count is at 40 at grant time: non-interactive (offline) silently wastes the drop; interactive (live) holds it as `pendingFullDrop` and `InventoryFullModal` (mounted unconditionally in `GameShell`) asks the player to discard an existing gear item or potion stack, or discard the new drop — never auto-resolved. Stone tiers aren't offered as a discard option (low-risk gap, no stone-drop mechanic exists yet).

## Equipment / Hero page

Paper-doll layout, class-specific slot arrangement, quality-glowing tiles, tap-to-unequip, hover tooltips, total stats at top.

- **`EquipmentPanel.tsx`/`EquipmentSlot.tsx`**: CSS-grid paper-doll (`gridTemplateAreas`, capped `max-w-sm`, centered). Tiles are fixed pixel size (`SLOT_SIZE = 'h-24 w-24'` desktop, `h-16 w-16` mobile) — grid columns govern position only, not tile size.
  - **Slot arrangement** (current, final): `gridTemplateAreas: '". head ." "neck . ring" ". armor ." "offhand . main" ". boots ."'` — five rows alternating center-only (Head, Armor, Boots) with sides-only (Necklace+Ring, then Off-hand+Main Hand), so side pairs land vertically centered between the center rows above/below via the grid's own even row spacing. `gap-y-3 lg:gap-y-4` / `gap-x-2 lg:gap-x-3`. Same arrangement for every class.
- **Multi-slot equipping**: Head/Necklace/Ring/Boots/Armor (`hat`/`necklace`/`ring`/`boots`/`coat`) plus Main Hand (`weapon`) are all functional, driven by `useEquipmentStore.equippedIds: Record<EquipSlot, string|null>` and matching `characters.equipped_weapon_id`/`equipped_ring_id`/`equipped_necklace_id`/`equipped_boots_id`/`equipped_hat_id`/`equipped_coat_id` columns, each `on delete set null`. Clicking a filled slot toggles a detail card (name/quality/level/stats + Unequip). Equip happens from the Inventory grid via `setEquippedItem(template.slot_type, item.id)`. **Off-hand/Shield is a locked placeholder for every class except Hunter** (no shield `item_family` exists yet) — Hunters get the functional Quiver there instead.
- **Quiver**: single starter template `"Hunter's Quiver"` (`slot_type: 'quiver'`, `item_family: 'quiver'`, no stats, no upgrade chain), auto-granted+equipped at Hunter creation (`grantStarterQuiver`). Having it equipped IS the entire ammo mechanic (see `CLAUDE.accounts-and-classes.md`). Buyable in Shop if lost/sold. Excluded from random kill-drops (`NON_DROPPABLE_FAMILIES`). Equip/unequip goes through the same generic slot path as everything else, no special-casing.
- No central character portrait/placeholder — removed entirely (was an abstract SVG box, `PaperDollBody.tsx`), freeing the center grid column to grow the surrounding tiles instead. Not revisited.
- Every functional slot shows the universal `ItemTooltip` on hover when equipped (`getItemIcon(template.slot_type)` for icon). The remaining locked Off-hand placeholder (non-Hunters) keeps a plain native `title`.
- **Known consequence**: Forge-upgrading any equipped item requires unequipping it first (Forge's `InventoryPanel` copy hides equipped gear the same way Inventory does).

## Consumables

**HP and Mana potions** — manual-use only, not auto-triggered in combat.

- Real discrete-stack inventory (`potion_stacks` table: `id`/`character_id`/`potion_type`/`count`, `src/game/items/potionTypes.ts`, `usePotionStore.ts`). Buying always purchases a stack's full `stackSize` (20) for `stackSize × price` gold, topping up an existing non-full stack first. Not class-restricted.
- Use button in the potion's Inventory detail card. HP potions call `useCombatStore.healPlayerHp(amount)` (clamped to max, disabled "HP already full" at max). Combat page's player-HP card surfaces the single best-available HP potion with inline Use (scans `HP_POTION_ORDER` strongest-to-weakest); shows "No HP potions — visit the Shop" when none owned.
- **Mana potions are real, buyable, tradeable, but honestly inert** — no `currentMp`/`maxMp` tracking exists yet (nothing drains MP), Use is disabled with "Nothing to restore yet" (matches the established "data exists ahead of the mechanic" pattern used for sockets/dodge before their mechanics existed).
- Potions occupy Inventory slots exactly like Composition stones (one non-empty stack = 1 slot, counted in `occupiedSlotCount`). Offered as a discard option in `InventoryFullModal`.
- Tier roster (8 each, required levels 1/20/40/60/80/95/110/125): HP — Sprigroot Tonic → Verdant Balm → Emberleaf Draught → Ironbark Elixir → Stormroot Brew → Duskflame Panacea → Skyfire Elixir → Wyrmheart Draught (25→400 HP, 3→130 gold). Mana — Mossglow Tonic → Whisperleaf Draught → Moonpetal Elixir → Starlight Brew → Emberwind Panacea → Nightbloom Draught → Voidglass Elixir → Astral Draught (8→130 MP, 3→130 gold). **All heal amounts/prices are PLACEHOLDERS, unresolved.**
